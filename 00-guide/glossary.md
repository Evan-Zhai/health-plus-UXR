# 词汇表

给非研发背景的设计师：仓库里的英文文件夹名和常见产品词。

| 词 | 意思 |
| --- | --- |
| Brief | 项目简介：做谁、解决什么、不做什么、成功长什么样 |
| Discovery | 发现问题的阶段：访谈、桌面研究、竞品，先不画高保真 |
| Insight | 从原始材料里提炼出的、能指导设计的判断 |
| Persona | 人物画像：一类用户的目标、障碍、情境（用虚构代表，不写真人） |
| Journey map | 体验地图：用户在一段时间里的步骤、情绪、断点 |
| Opportunity | 机会点：我们决定切入的那一个问题，比「做个页面」更上游 |
| Iteration | 迭代：根据新证据改策略或方案，并记下为什么 |
| IA（Information architecture） | 信息架构：内容怎么分组、导航怎么叫 |
| User flow | 用户流程：完成一件任务要点哪些界面、哪几个决定 |
| Wireframe | 线框：先结构后视觉，灰盒子即可 |
| Prototype | 原型：可点击的流程，用来走查和可用性测试 |
| UI design | 界面设计稿：带真实组件、颜色、字号的视觉稿 |
| Exploration | 探索稿：没被选中的方向，也要留，避免以后重走弯路 |
| Critique / Review | 评审：针对目标提问题，不是评「好不好看」 |
| Design system | 设计系统：跨项目共用的原则、基础、组件、模式 |
| Token | 设计变量：颜色、间距等的名字，方便和开发对齐 |
| Pattern | 模式：多个组件组合成的常见用法，如「表单报错」 |
| Handoff | 交付 / 交接：把设计意图讲清楚给工程和 QA |
| Spec | 说明：状态、空态、错误、断点，比标注尺寸更重要 |
| QA | 质量走查：对照设计看实现差在哪 |
| WCAG | 网页无障碍标准；对外产品默认按 2.2 AA |
| PHI / PII | 个人健康 / 身份信息；本仓库禁止出现真实值 |
| GreenShield Plus | 本仓库服务的产品工作空间名称；具体产品范围以项目 Brief 为准 |
